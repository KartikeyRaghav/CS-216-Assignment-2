We understand from this one complete hash of transaction B->C that it contains all the required information for the given transaction. 
It starts with the version number followed by the hash of the input being used. This hash is used to refer to the input transaction and hence the locking script that was associated with it. 
The next bytes represent the input script or the unlocking script that contain the signature and the pubkey that are used against the locking script to prove that this transaction can use the previous UTXO. 
Once the signature and pubkey are verified the transaction can take place. The previous UTXO is destroyed and new UTXO is created. Since there is no change left (i.e. all the amount of the previous UTXO is being sent) only one output exists.
A new locking script is created with this transaction that contains the hash of the public key of user C. When C wants to spend this UTXO, this locking script will be checked against the signature and the public key provided by the user C.
To check that the UTXO being spent belongs to the spender, the locking script follows the below procedure.
<signature> <pubkey> OP_DUP OP_HASH160 <pubkey_hash> OP_EQUALVERIFY OP_CHECKSIG
This is a stack based algorithm. The user provides their signature and public key which are pushed into the stack.
The script duplicates the <pubkey> present at the top of the hash and pushes it into the hash.
The already present <pubkey_hash> in the script is then pushed into the stack.
The OP_EQUALVERIFY function then pops out the top two elements and compares them. If they are equal then the script proceeds further otherwise stops.
The OP_CHECKSIG then pops out the <pubkey> and <signature> present in the stack and verifies that the signature belongs to the provided pubkey only. If true a 1 is pushes into the stack. This marks the end of the algoritm.  

The full process is that we created a wallet named testwallet under which we created 3 legacy addresses (A, B and C). We first send 10 bitcoins to A(since we are in regtest we can directly send bitcoins using the function sendtoaddress(<address>, <number_of_bitcoins>)).
We then get the utxo set and find the utxo that is owned by A. This utxo has information of owner address, amount and the locking script which must be unlocked using the signature and the pubkey of the owner.
This utxo is then used as an input to send the bitcoins to B. A fee of 0.001 BTC is charged and a new locking script is created with the pubkey_hash of B. The previous UTXO is then destroyed and a new UTXO is created that has the address of B.
This new UTXO is then used in a new transaction of sending the bitcoins (now 9.999 BTC) to C with a fee charge of 0.001 BTC. The locking and unlocking are done again using the signature and pubkey of B and pubkey_hash of C respectively.
The new UTXO generated is now addressed to C and can be used for a new transaction when the signature and pubkey are provided.
